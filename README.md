# pose-animate

Framework-independent, deterministic SVG character rendering for Zog. **Skiff** is the first character.

## First implementation (0.1)

Skiff head size was reduced by **30% in width and height** following visual review; the face scales with the head, while the 48 limb squares retain their size. The rendered roots are pulled toward the new head boundary and the limb tips stay in place. Pose vocabulary is unchanged pending later animation improvements. GitHub Pages is intentionally not enabled.


- Canonical square-headed character with eight independently addressed limbs and six square segments per limb (48 total).
- Pure `renderSvg(frame)` function and named immutable pose definitions.
- Six discrete color palettes, face expressions, deterministic quantized idle movement, inward/outward light pulses.
- Minimal DOM adapter with automatic reduced-motion support and lifecycle cleanup.
- Static browser playground with pose, palette, face and pulse controls.
- Unit tests and GitHub Actions CI.

**Visual approval is still pending.** The geometry in this initial implementation is a hand-authored interpretation of the approved Skiff variation #3, not a pixel-traced match. Preserve the geometry gate before treating this as the production mascot.

## API

```ts
import { createSkiff, renderSvg, poses, samplePose } from '@zog/pose-animate';
const actor = createSkiff(document.querySelector('#skiff')!, {palette:'blue',reducedMotion:'auto'});
actor.setPose('greet');
actor.setExpression('happy');
actor.pulse('outward');
actor.destroy();
```

`renderSvg({pose:samplePose('idle', 1.5),palette:'blue',pulse:'none',phase:0})` generates deterministic standalone SVG. Application status UI is explicitly out of scope; this module draws the character only.

## Third pass: coordinated gestures and semantic presentations

The pose sampler now moves all six squares of each limb with delayed, deterministic
waves; primary limbs lead while secondary limbs provide counterbalance. All limb
squares remain axis-aligned and the smaller head is unchanged. Focused,
concerned, sleeping and surprised faces have different pixel geometry.

`semanticPresentation(state, mood)` maps factual states to a named pose, a face,
and an inward/outward/none signal pulse. The browser adapter adds `setState`,
`getState`, and `setMood`. Critical factual states (connection-interrupted,
warning, error and sleeping) take facial precedence over cheerful moods or manual
expression overrides. Color remains a separate presentation choice; applications
must also expose factual statuses accessibly in their ordinary HTML.

The standalone offline preview includes distinct state and mood dropdowns. Choosing
an explicit gesture exits semantic state mode. Reduced-motion mode keeps the
static pose and disables traveling pulses. GitHub Pages remains intentionally
unconfigured pending review.
## Fourth pass: curled limbs, joined mouth and foreground thinking tip

The distal squares of each limb now curl gently inward to reduce the spread
while retaining eight limbs of six squares each and the 30%-smaller head.
Every expression uses a continuous orthogonal pixel mouth instead of three
separate dots. Pondering places the last three limb squares visibly over the
face using SVG references, so no additional unique limb squares are created.

Existing motion, semantic states, moods and reduced-motion handling remain
unchanged. The standalone HTML remains the review mechanism; GitHub Pages
stays disabled until visual acceptance.

## Ponder tip position refinement

The same ponder gesture used by `thinking`, `working`, and `connection-interrupted`
now rests at the **left of Skiff's mouth/chin** rather than near his nose.
Its animated swing is constrained to stay at chin height, including after the
shared tentacle curl. The existing joined mouth and all other gestures remain
unchanged. GitHub Pages remains disabled while visuals are reviewed.

## Skiff 0.2 — expressive animation laboratory

The first four-part animation milestone is implemented on the `unstable` branch:

1. **Distributed articulation:** movement propagates along the six square segments of each tentacle; a transverse wave provides subtle follow-through without rotating rectangles.
2. **Declarative multi-stage choreography:** the pure `sampleSequence(name, elapsedMs, motion)` API samples named sequences without clocks or browser access. Three scenarios are included: `request-flow`, `connection-recovery`, and `greeting`.
3. **Separate interruption and recovery:** connection interruption maps to a drooping `droop` pose with no illumination pulse; `recovering` raises the tentacles and resumes outward light flow. The approved `ponder` tip remains by the left mouth/chin for thinking and working.
4. **Offline timeline playground:** choose a scenario, Play, Pause/Resume, Replay, Stop and scrub a timeline. Existing pose, mood, state and palette controls remain available.

**Stable browser API:** `skiff.play(name)`, `pause()`, `resume()`, `replay()`, `seekSequence(ms)`, `stopSequence()`, and `getPlayback()`. A manual state or pose selection interrupts scenario playback. Reduced motion retains state changes and static poses but removes continuous motion and traveling pulses.

This is a **development preview, not a published release**. Visual approval remains pending, and **GitHub Pages remains disabled**.

### Release gate

Before publishing on GitHub Pages, check visual consistency, accessibility, multi-stage choreography, smooth interrupted transitions, mobile viewport handling and deterministic test coverage. Do not treat the experimental scenario durations as host-welcome operational timings.

## Skiff 0.3 — integration readiness (Steps 1–2)

Five deterministic SVG visual baselines (idle, thinking, working, interrupted, recovery) are pinned in `visual/baselines.v1.json` and checked in `npm test`. `node scripts/capture-visuals.mjs` generates inspectable SVG/HTML captures; optional `--png` attempts local browser screenshots. The CI preview workflow publishes visual review artifacts alongside the offline playground.

Host applications should import `createSkiffPresenter` from `@zog/pose-animate/presenter`. This narrow semantic interface owns `setState`, `setMood`, `playSequence` (a settling completion/cancellation promise), `stop`, `subscribe` and `destroy`. It keeps application facts and accessibility independent of visual animation. See `docs/INTEGRATION.md` and `docs/VISUAL_BASELINES.md`. This is a development candidate, not a formal release. The host-welcome demo and GitHub Pages remain deferred.
